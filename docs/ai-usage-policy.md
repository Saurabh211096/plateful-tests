# AI usage policy (one page)

Kestrel Bay gives each team member a seat on a company-approved AI assistant ("the AI seat"). Used well, it saves time. Used badly, it leaks client data or puts wrong work in front of the client. Version 1.2, approved by Vikram Kulkarni, October 2026.

## Good uses

- First drafts: test case ideas, test data, a bug title, an email.
- Explaining an error message, a log, a piece of code or a term.
- A first version of a SQL query or an automated test, which you then check and fix.
- Shortening or summarising long text that contains **no client or customer data**.

## Never put into the AI seat

- Passwords, OTPs, API keys, tokens, cookies, card numbers.
- Customer data of any kind: names, phone numbers, addresses, emails, order details from Production or support tickets. Mask or replace them first.
- Plateful's confidential documents: contracts, pricing, plans that are not public.
- Source code of the Plateful app.

The Plateful ticket text (stories and acceptance criteria) may be used, after removing any customer data.

## You are responsible for the result

- **Check everything** the AI gives you against the ticket, the [Plateful rules](plateful-rules.md) and the real app. It does not know Plateful's rules and it can be confidently wrong.
- Never send AI output to the client or a teammate without reading and correcting it.
- When the AI seat helped with a piece of work, say so in one line in your update or pull request, for example: "First draft of test cases from the AI seat; reviewed and corrected (added 4 boundary cases)".

## Use it sparingly

Think first, then ask. If the AI seat is doing the thinking, you are not learning the job.

## Where

Only the company AI seat. No other AI tools or browser extensions for work data.
